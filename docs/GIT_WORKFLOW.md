# Git workflow

Use protected `main` for production releases and `develop` for integrated QA work:

- `feature/*` branches from `develop`, merged by reviewed pull request
- `release/*` branches from `develop`, stabilized in QA, merged into `main` and back into `develop`
- `hotfix/*` branches from `main`, tested, merged into `main` and `develop`
- Annotated semantic-version tags on production commits

Require CI checks, review, no force pushes, and secret scanning. Keep application changes separate from infrastructure changes so rollback is understandable.

Before a clean commit, review existing modifications, remove tracked generated bytecode from the index, and audit history for secrets:

```bash
git status --short
git rm -r --cached -- 'backend/app/**/__pycache__'
git ls-files | grep -E '(^|/)(\.env|certbot/conf/accounts|.*\.pem|.*\.key)$'
```

On PowerShell, use `Select-String` instead of `grep`. If a real secret entered history, ignoring it is insufficient: rotate it first, then coordinate an approved history rewrite.
